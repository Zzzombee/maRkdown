# 拆解文档准入门槛

## 适用范围

仅用于面向项目故事的文献拆解与目标图片大纲。普通论文阅读不执行本门槛；该排除不允许在故事映射任务中绕过完整性检查。

## 目标

只在项目内已存在用户指定的完整论文故事线时，允许搜索或拆解模板文献。门槛评估的是目标论文逻辑和试验方案是否完整，不是当前结果是否齐全。

## 定位目标故事

1. 从用户指定的故事标题、稳定 ID、SOL 或项目文件定位目标。
2. 先检索标题、ID 和核心关键词，再读取目标条目及理解其逻辑所必需的直接相关条目。
3. 故事必须已存在于项目文档内。用户在对话中临时口述的构想不能代替项目内的完整故事线。
4. 如果存在多条可用故事而用户未明确指定，请用户先选择；不按“最新”“主故事”或匹配度自行替用。

## 完整性判定

同时满足以下五项才通过：

1. **中心问题与目标主张。** 能说明论文要解决什么问题，以及完成时要建立什么核心发现或能力。
2. **端到端论证链。** 能按先后顺序列出支撑核心主张的所有中央逻辑环节，并说明每一环如何连接下一环。
3. **可执行的试验方案链。** 每个中央逻辑环节都有对应的实验或分析类型、核心对照、主要 readout 和判定用途。不要求已记录每个操作参数。
4. **终点与价值闭环。** 能说明最终功能、应用、机制判别或其他论文终点如何回答中心问题。
5. **可组织为完整主图链。** 不补造缺失的中央逻辑桥接，就能为目标论文列出从第一幅到最后一幅主图的任务及对应实验。

最终自检问题：

> 不发明新的核心主张、关键过渡或主要实验路线，能否直接写出一条完整的目标论文主图链？

答案为“否”时不准入。

## 不影响准入的因素

- 当前数据是否完整、显著或达到投稿质量。
- 某些预计实验尚未完成。
- 当前 CON 或其他证据层级较弱。
- 用户未提供原始数据、分析文件或已排版图片。

这些因素可影响项目实际进展，但不影响“是否已存在完整论文逻辑/试验方案”的判定。

## 失败时的固定行为

1. 不创建任何拆解文档、文献推荐产物、panel 图片或 PPTX。
2. 不开始外部文献搜索；如果用户已给文献，也不继续拆解。
3. 简明列出已找到的故事部分和缺少的中央逻辑环节。
4. 告知用户需先在项目内补全故事或试验方案。只有用户另行要求时，才进入故事建立或文档维护工作流。
