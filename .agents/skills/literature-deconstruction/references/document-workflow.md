# 拆解文档工作流

## 1. 确认输入和产物位置

- 记录用户指定的故事线和已通过的准入结论。
- 确认是用户指定文献，还是先推荐文献。
- 先读取项目 `.agents/instructions/project-layout.md`。原文和补充材料放入 `sources/literature/<paper-key>/`，拆解正文放入 `notes/literature/`，PDF 页面渲染放入 `.work/deconstruction/<paper-key>/rendered/`；只有显式请求 PPTX 时才在该工作目录创建 panels/、图片映射文件和 qa/，正式 PPTX/PDF 放入 `outputs/deconstruction/<paper-key>/`。用户指定目录仍须遵守项目目录合同，不恢复顶层 staging/ 或 output/。
- 交付后默认保留暂存目录，以便核对来源、panel 裁图和重建产物；用户明确要求清理时才删除。不把中间文件散落到核心项目文档目录。
- 若任务包含较多 panel、多份 PDF 或可能跨会话，可在暂存目录创建精简 `run_state.md`；它不是正式研究产物。

## 2. 文献选择与核验

### 用户指定文献

1. 核对题名、作者、年份、DOI 和正式全文。
2. 取得主文图注和必要的补充材料。
3. 核查更正、撤稿、关注声明及其他会改变解读的来源状态。
4. 如果必要补充材料无法取得，先判断缺失信息是否会实质改变 panel 身份、关键对照、直接结果或项目映射。若会，停止或缩小拆解范围，不推测缺失内容；若不会，可生成明确标注“未核对补充材料”的主文限定版本。

### 用户要求推荐文献

1. 按 `literature-source-gate` 的来源、核验和证据规则检索。
2. 优先比较论文的中心问题、主图论证顺序、关键对照、readout、时间尺度和终点，而不是只比较题名关键词或材料名称。
3. 默认选出一篇最适合作为“图片组织模板”的文献，并说明它与目标故事的结构匹配以及不能直接外推的体系差异。
4. 只有用户明确要求多篇时才交付多篇候选或多文献并行拆解。

## 3. 先按文献自身逻辑拆解

1. 视觉核对全部主图、panel 标签、图注和正文对应段落。
2. 先不引入项目故事，用一段话写清论文从问题到结论的主图顺序。
3. 原则上每个 panel 单独处理。只有相邻 panel 构成同一测量链，且拆开后会重复同一功能说明时才合并。常见情形是代表图与紧邻定量，或拟合结果与残差。
4. 每个 panel 的“文献”段使用短句依次说明：
   - 图中是什么：对象、操作、分组和 readout。
   - 作者得到什么：只写图中直接可见或统计支持的结果。
   - 论文中做什么：它建立哪一层证据、排除哪个解释或连接哪两步。
5. 作者讨论、机制模型和 panel 直接结果必须分开。

## 4. 再映射到完整项目故事

1. 将文献 panel 的“论证功能”映射到目标故事的对应逻辑环节，不要求项目复制文献的具体材料、模型或技术。
2. 每个 panel 的“本项目”段只回答：
   - 为完成这一逻辑环节应做什么实验或分析。
   - 应放什么代表图、定量图、对照或模型图。
   - 这张图在目标论文中建立什么、排除什么或连接什么。
3. 默认不写当前数据已有与否、当前 CON 强弱或项目进度。项目 ID 可在主图大纲后作为路线依据，不得打断 panel 正文。
4. 使用“比较”“检验”“展示”“量化”“用于建立”等设计语言，不虚构结果方向、效应量或统计显著性。

## 5. 补充材料路由

不全量拆解补充材料。只纳入直接承担以下任务的部分：

- 主张成立所必需的关键对照。
- 排除替代解释或限定机制边界。
- 建立长期功能、重复性或安全边界。
- 对项目目标图片链有明确映射作用。

在文档中用一句话说明每组补充 panel 的纳入理由。

## 6. 填充正式模板

使用 `assets/literature-deconstruction-template.md` 的固定顺序：

1. 文献与目标故事的结构对应。
2. 逐 panel 拆解与本项目对应。
3. 本项目目标主图大纲。
4. 成文链条。
5. 来源核验与证据边界。

不使用 Markdown 表格，不在表格中放链接，也不新增状态评分卡。

## 7. 可读性与交付

1. 完成上游事实核对后，调用 `academic-writing-editor` 优化句子。
2. 一个句子尽量只承担一个功能，技术术语保留，但要说清它在当前 panel 回答什么问题。
3. 随机抽查 panel，确认读者无需返回图注就能理解图、结果、论证作用和项目实验。
4. 用户未明确要求 PPTX 时，交付 Markdown 后结束，不顺带创建演示文稿。
