# 从进展到汇报

## 最小内部候选记录

按实验批次或一个实际问题建记录，原始文件、分析结果、图和笔记合并在同一项。字段：实际/待核实日期、相对上次新增内容、来源路径、关联项目问题、实验与对照、重复层级、可复用分析/图、QC/冲突、可用程度、处理动作、候选展示信息点。

记录放内部，不把几十行候选表转交给低精力用户挑选。没有实验日期时保留 unknown，不以 mtime 补造。上次汇报无法核实时只能说“近期材料”，不能断言全部是新增。

## 可用性判断

| 状态 | 判断条件 | Agent 接下来做什么 |
|---|---|---|
| 可直接展示 | 来源、条件、指标和现有分析能支持一条范围明确的观察 | 选合适的图和朴素标题，核对全体相关记录 |
| 轻量处理后展示 | 数据存在，只差拆表、统一明确单位、复用已有汇总或核对一个字段 | 自行处理并验证；不把这个动作留作用户待办 |
| 可报告进展或未定结果 | 真实完成的工作清楚，但因对照、重复、漂移或质量问题无法支持预期结论 | 陈述完成的工作及实际观察，给出具体未定点；必要时展示相反或失败数据 |
| 本次暂不使用 | 来源不明、关键条件冲突无法解决、分析无效或解释成本超出本次任务 | 内部记录理由；若影响主结论，在汇报中说明该缺口 |

同一数据可能适合展示现象，但不适合机制判断。说明“用于什么主张”的可用性，不给整份数据一个泛化的合格/不合格标签。

源表不是无需核对的最终权威：对应实际记录、已有分析代码和项目状态。新旧分析冲突时定位条件/版本差异，按项目证据规则处理。未知字段须核对定义，必要时不纳入汇报；用户无需先学完整个参数表。

## 选题与展示

- 先比较实验与可比对照、重复间一致性和相反结果，再决定重点；不要把最新、最漂亮或最方便导出的图自动排第一。
- 每个主图回答一个具体问题。展示需要依据比较关系决定：时序用完整轨迹；重复性用个体点或配对；不同协议/批次并列时保留条件差异；协议不可比时不强行合并绝对值。
- 代表性轨迹必须与相关全体记录核对，选择理由不能是效果最大。必要时给多条轨迹或个体汇总。
- 区分展示量与统计量：平滑图不改变计算输入，统计 n 不由数据点数替代。没有已核实分析时优先描述性表达，不能给现成图补一个猜测的显著性标记。
- 每页标题贴近数据，不强迫每项结果找上位概念。机制只能在证据允许时提出，并保持假设标签；周报不必包装成论文故事。
- 简洁性不能删除对当前判断有用的多维 readout。先核对各维度的结果与已有推论，再决定合并或暂缓；例如 multisine 的五频平均不能替代实部、虚部、相位及其支持/不支持的解释。无需新增上位概念，但应保留项目已有、与数据相称的推论。

## 输出结构示例（需填入真实内容）

主文件 `本次汇报.md`：开头用两三句明确本次重点与覆盖时间，然后按讲述顺序逐页写：
1. 页标题和本页回答的问题。
2. 已选数据/现有图的具体链接；需要重画时注明已经生成的作图表、列、比较对象与图形安排。
3. 可直接讲的两三句话，以及真正影响理解的限制。

默认到此完成交付，不继续制作新图片。展示安排写清图形、数据列和比较对象即可；用户已明确要求节省 token，不能将“主动完成”扩张为自动制图、排版或重复渲染。

所有条目都需具体化后交付，不能把此模板或“建议整理对照数据”当作成品。若位于本 Obsidian 项目，项目 ID 链接遵循 AGENTS.md；对话中使用标准本地文件链接。

低精力不是省略关键判断。默认不做新文献综述或大型新分析；需要这些才能成立的内容降低主张范围或暂缓，继续完成可交付部分。
