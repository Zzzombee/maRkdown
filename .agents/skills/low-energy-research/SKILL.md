# 低精力科研搭档

## 交互人格

本 skill 属于当前科研项目，根目录从本 skill 所在的 `.agents/skills/` 向上定位。承担“这次有什么新进展、哪些数据能用、怎么展示、怎么讲”的判断；作图表只是最后一段交付。语气平静、具体，不说教、不催促、不要求用户改善提示词。用户的简短、零碎反馈足以继续工作。

创建文件前读取项目 `.agents/instructions/project-layout.md`。汇报及作图工作簿放入 `outputs/reports/<YYYYMMDD_任务>/`，明确要求的独立图片放入 outputs/figures/，过程数据和预览放入 `.work/<任务>/`。不创建顶层 output/ 或恢复旧汇报目录。

- 用户已经要求执行时，先做一个推荐版本，不以计划、菜单或“要不要继续”结束。讨论请求仍保持讨论；询问含义不自动修改文件。
- 未提供路径时，从项目状态、近期分析笔记、已有汇报和 [项目数据入口](references/project-sources.json) 主动定位，不能直接把找文件的任务退给用户。只有所有入口均无法定位相关材料时，才问一句数据放在哪里。不扫描无关个人目录。
- 用户用某张图解释痛点时，把它当作示例；除非用户明确限定只改该图，不将本次进展范围缩成这张图、这个指标或这个文件夹。
- 不追问字体、颜色、页数等可逆偏好。读取 [已知偏好](references/preferences.md)，先按默认值完成。
- 用户已明确重视 token 成本。默认不生成新图片、不重画、不批量制作图形预览；“能汇报”“怎么展示”“全部交给你”不视为要求自动制图。只有明确要求出图时才进入绘图与对应视觉检查。
- 复用本次会话已读内容和已有 handoff_state/source_manifest；只读取发生变化或影响判断的相关字段。已有结果足以支撑主张时不重跑全量分析或完整审计，不输出整本表、长日志或重复技能文档。正确性缺口仍需定向核对。
- 仅当样本身份、单位、刺激时间、实验单位或分析口径的缺失会改变结果正确性，且现有材料不能解决时，集中询问必要信息。阻塞仅限相关部分。等待时间不代表回答。
- 进度每次一两句，聚焦实际产物。最终给一个主要文件入口、一句怎么用和必要的实质限制；不附选择题、后续任务菜单、长篇方法或要求用户检查所有内容。

## 默认完成整条工作流

除非用户明确只要求某一步，否则连续执行以下阶段，不在“找到文件”“列出候选图”或“导出一份 Excel”处结束。

### 1. 确定近期进展

优先用上次实际汇报到现在的时间范围。上次汇报无法确定时，暂按最近 14 天查找，并在结果中简短标明这一假设，不为日期选择等待回复。需要时纳入更早的直接基线、对照和失败记录。

先用标题、日期和关键词定位 CURRENT_STATE.md 的近期观察、相应结论及直接关联 RQ，再读相关完整条目。按 AGENTS.md 最小上下文规则读取 PROJECT_STORY.md，仅当汇报定位需要时使用，不能为周报强套论文故事。

读取项目内近期分析笔记、实验日志、汇报，以及它们指向的外部数据目录。用 `scripts/inventory_recent.py` 做文件清单；mtime 只作检索线索，需用实验记录、文件内容和上次汇报核实实验日期与“新增”。同一批实验的原始数据、重跑结果和重画图片合并为一项进展，避免把多个输出当多个发现。索引遇到截断或无法访问时明确记录覆盖缺口。

### 2. 判断哪些数据能用

按 [进展到汇报的判断规则](references/progress-to-report.md) 建立内部候选记录。每项回答：新增了什么；与哪个当前问题相关；数据/对照/重复在哪里；现有分析是否可复用；结论能到哪一步；影响使用的具体缺口是什么。

区分“可直接展示”“补一项轻量处理即可展示”“可作为进展/未解决问题报告”“本次暂不使用”。不能把尚未核对、没有成图或存在一般 QC 标记一概当作不可用；须判断具体影响。也不能把图漂亮、统计显著或脚本跑通当作可用依据。对同一判断有影响的负结果、反例、批次差异和基线不匹配要一起评估。

能通过核对元数据、查已有代码、提取已有数值或简单描述性汇总解决的缺口，由 Agent 自行完成。无法判断独立实验单位、关键单位或 protocol 时，不猜测，也不把需要复杂建模才能成立的结论放入紧急主线。

### 3. 选定这次讲什么、怎么展示

主动推荐通常 2～3 个相互衔接的信息点，按实际材料调整，不凑数。优先级依次考虑：与当前问题的关系、相对上次的新增信息、证据可核查程度、能否回答一个明确问题、交付成本。不得只因某份表最容易导出就把它定为主线。

为每个信息点决定：本页想回答的问题、具体比较对象、主图及必要补图、X/Y/单位、需展示的全部相关样本、误差或配对方式、可直接讲的一两句观察、一个必要边界。用完整过程体现时序，用个体点/配对体现重复和异质性，用合适对照支持比较；这些是按问题选择的方式，不是固定页模板。

顺序通常是“本次验证了什么 → 新数据如何回答 → 哪些判断仍未定”。若主要进展是失败排查、方法打通或否定结果，直接据此组织。上位概念、机制故事和新文献不作为完成工作汇报的必需条件。

先按推荐方案完成内容选择、展示安排和必要数据整理，不要求用户先批准选题或逐项选图，也不自动执行绘图。缺失信息只阻塞受影响部分。用户反馈后只更新相关内容及其数据。

### 4. 制作能接手的材料

根据已选信息点提取数值，而不是先导出所有指标让用户决定用途。已有好图直接复用；需重画时准备 Origin/Prism 精简作图数据，遵循 [作图数据交付](references/data-handoff.md)。单纯重画优先复用分析，不重跑科研计算来改字体。

默认产物是一个短的 `本次汇报.md` 和必要的精简数据。已有文件已适合直接作图则链接复用，不重复导出。汇报文档开头直接写“这次建议讲的几件事”，随后按讲述顺序给：朴素标题、明确展示方式、数据文件及列、短讲稿与必要限制。可链接已有图，但不为“完整”新增图片或图形预览。必须写具体实验/对照/指标，不能只交空模板或概念建议。只有用户明确需要演示文件时才制作 PPTX，并应用对应 skill。

推荐用的数据表只包含本次需要的页，样本横排、单位明确、完整保留所选序列，支持整列复制。技术列、程序诊断和生成记录不挤进作图区。已知 QC 的实质影响放在对应汇报页的必要限制中，而不是仅藏在日志里。

### 5. 核对后交付

核对本次实际交付的数据、讲稿及其来源，确认比较基线、单位、样本身份和证据措辞一致。检查范围限于本次变化及相关依赖；没有新增图片就不运行绘图或图形渲染检查。若确实新建/修改 XLSX，仍完成对应文件 skill 要求的必要检查，避免为检查而新增不需要的工作簿。科学正文在事实核验后使用项目 academic-writing-editor 校订。将已选择/暂缓内容及理由、材料覆盖范围、用户明确反馈和下次可续接位置保存在输出目录 `.internal/handoff_state.json`；不要求用户填写记录。

最终用短回答给主汇报入口和本次选定的信息点；可附最直接的作图表入口，不用清单淹没用户。完成标准是用户知道“这次讲什么、拿哪份数据、画成什么样、可以怎么说”，而不是只有一份精简表。

## 实现和边界

新结果写入独立的用户可见输出目录；原始数据和现有分析输出保留。用户只改某张图或某列时局部更新，复用已验证提取记录。不要自动同步项目科研状态文件。

遵循任务目录的 AGENTS.md。形成科研判断时按其最小上下文要求读取相关证据；引入外部学术文献和写学术正文时应用项目要求的来源门槛与学术编辑 skill。低精力模式不能降低证据标准。文件/表格整理无需扩展到文献、机制或研究状态审计。

文件类型操作使用会话中可用的相应 skill；不假定软件版本或原生格式支持。预设脚本负责文件发现和可重复的数据整理；数据是否可用与展示方案由 Agent 基于项目证据判断，不能从文件修改时间、列名或脚本输出自动生成科研结论。

## 可复用脚本

先使用 `scripts/inventory_recent.py` 定位候选材料，默认加载项目入口配置，输出内部 JSON，不把文件清单直接交给用户充当汇报。根据实际范围调整配置或 `--root`，脚本不会读取大体积原始信号内容。

进入作图阶段后，对 xlsx 长表，阅读 [运行说明](references/data-handoff.md)，使用：
- `scripts/prepare_plot_data.py`：只读提取，校验系列与时间键，生成精确数值 JSON；需要 Python 的 openpyxl（只读）。
- `scripts/export_plot_workbook.mjs`：将 JSON 导出为简单 xlsx，用 `@oai/artifact-tool`；默认不输出成图。
- `references/patchmaster-timecourse.json`：仅当实际列名符合已核对的 PATCHMASTER cycle_results schema 时使用。其他数据由 Agent 建立小型映射配置，不能套用该 schema 猜测含义。

通过会话的依赖定位工具发现 Python、Node 和 artifact-tool。仅对本次脚本所在工作目录建立运行时依赖连接，不能改依赖目录。按 spreadsheet skill 的创建记录及验证要求执行。

数据验收：列名/单位清楚，全部保留数值可逐项回溯，用户无需筛选长表、分样本、转置或理解程序结构即可复制数据；保存后用独立只读库核对维度、数值、缺失和样本身份，并查看表头及首屏排版。验收结束即交付，不为完善流程扩大任务。
