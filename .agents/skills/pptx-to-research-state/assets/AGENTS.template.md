## Scope and context

文档和实验细节问答默认只读；明确要求修改、补充或同步时才写文件。执行请求持续到产物和适用检查完成。可逆偏好用合理默认值；缺失关键参数时只暂停受影响部分，不猜测或无限扩展研究方向。

先按标题、稳定 ID 和关键词定位，再读取目标完整条目及必要直接关联内容。事实、证据边界和关键参数足以完成当前任务时停止扩展，不递归加载全项目。

- 纯文件、格式、代码或工具任务不读科研状态文件。
- 事实录入/结果整理读 CURRENT_STATE.md 相关条目；实验设计再读相关 RQ。
- SOL 读指定 RQ、直接关联 OBS/CON/HYP 和已有 SOL；仅在路线取舍需要时读相关 Story。
- 论文定位、创新性和故事排序读三个状态文件的相关章节；整体比较候选故事时才完整读 PROJECT_STORY.md。
- 全项目科研总结、知识库重构或科研状态一致性审计完整读三个状态文件；技能/指令维护不自动触发。

## Evidence and file roles

CURRENT_STATE.md 管事实、结论和假设；RESEARCH_QUESTIONS.md 管问题和优先级；PROJECT_STORY.md 管目标叙事；SOL-###_*.md 管指定 RQ 的候选路线。后两者不替代实验事实。冲突时以更新时间较新的实验事实为准并保留冲突。

OBS 只写直接测量、观察与统计输出；CON 链接 OBS，说明支持范围、限制、替代解释和证据强度；HYP 链接目标观察/问题并保持为未验证解释。不得补造实验参数或把解释写成直接观察。保留阴性、不显著、矛盾及未复现结果。

面对新结果，先描述数据，再限定支持和不支持的判断，至少考虑一种替代解释；提出机制时给出可区分竞争解释的实验。优先判别力和决策价值。

新结果先更新 CURRENT_STATE.md，问题/优先级受影响时更新 RQ，方案可行性受影响时更新 SOL，最后更新受影响的 Story。实质修改的研究笔记同步更新 date。

## Task routes

生成本文件时，只写入已存在的项目规则路径或当前可用技能名；不得生成必读却无法解析的链接。用户已有政策优先，不自动安装技能或复制依赖。

- 外部文献：项目存在 literature-source-gate 时先读取其入口，按指定来源/自主检索模式执行，来源、指标、例外及引文详细政策不在此重复。项目强制政策缺失时暂停依赖它的部分；不得自行放宽门槛。没有该政策的其他项目仍须核验身份、原文支持和来源状态，区分直接/间接/推测，不拼接不同体系为已证明机制，不补造来源或指标。
- 结构性修改或结构审计：使用可用的 maintain-research-state 及其 schema。合并修改后选一次风险适当的校验；纯文字、格式、日期和只读任务不做结构校验。没有该技能时用下方精简结构合同手动核对受影响条目，不默认全库审计。
- 学术正文：优先项目 academic-writing-editor，其次技能目录同名技能；事实和结构完成后再编辑。一般正文缺少编辑技能时按下方写作底线执行；SOL 的最终编辑仍为强制要求，缺少时报告并停止最终 SOL 生成。
- 从 PPTX 导入科研状态：使用当前 pptx-to-research-state 的对应分支；现有项目按增量更新，不重新初始化。
- 文件制作：用户选择和现有专用管线优先，否则使用当前文档插件；同一任务选择一个实现入口，不叠加冲突配方。

## Stable structure and SOL

OBS/CON/HYP/RQ/SOL 使用稳定三位编号，不重排或复用。首次分配前检索对应编号类；保留废弃编号。没有专门 schema 时，条目首段末保留对应小写 block ID，CON 链接 OBS，HYP 链接目标观察或 RQ。CON 证据强度采用初步/中等/较强/充分；已有项目采用其既定词汇。

SOL 只在用户明确要求指定 RQ 的方案时新建；初始化创建 AGENTS.md、三个状态文件、标准目录及目录控制文件，不创建 SOL。默认检索请求日前五年，超期经典或不可替代来源遵循项目来源政策并说明理由；用户指定来源和约束按适用政策处理。

一个 SOL 对应一个稳定核心路线和一个主 RQ；文件名以 SOL-###_ 开头，YAML 包含 title、date、status、solution_id、related_rq、core_route，首段保留 ^sol-###。core_route 概括模型、靶区、干预逻辑和功能目标，仅用户明确要求时改变；实质不同路线另建，暂缓/否定/取代路线保留原编号及文件。创建 SOL 与 RQ 回链同批完成。

方案先以核验文献和项目事实限定可行性，再拟合用户方向和约束；区分 prior art 已覆盖能力、本项目缺口和不可外推条件。不得为预设路线增强证据。完成科学结构及引用核验后执行强制学术编辑。

## Story and writing

Story 默认新增或更新在 PROJECT_STORY.md；用户明确指定其他载体时也保持六节名称与顺序：摘要式故事、领域背景与未解决问题、文献定位与创新点、论文论证链、本项目的独特基础、当前证据与成立条件。标题承担核心主张，不另设重复命题。详细职责遵循项目故事政策及当前 pptx-to-research-state 的故事工作流与模板；生成本文件时解析其实际可用路径。

摘要按体系已经完成并正式发表的完整论文叙述，未充足的证据链按所选故事路线的成功结果补齐，不使用“预期”“拟”“如果成功”等计划或条件措辞，不编造数值、样本量、统计结果、关键参数或引用。目标叙事身份在文档级说明一次；真实支持程度、阴性、矛盾及成立条件集中在第六节，链接实际项目条目。成功叙事不会自动成为 CON，不用于实际投稿或真实实验结果陈述。

第二节综述领域问题来源、已有研究进展及其解答不足，不写本项目缺少的实验或对照。第三节分别保留“已有研究覆盖的能力”和“本研究的创新贡献”，用短条目突出贡献。第四节只写结果命题与论证作用，第五节只写实际基础，避免重复详细实验台账和证据限制。默认不生成额外评分卡或多层故事目录。

PPTX 内未经核验的文献主张保持待核验背景。新颖性判断须执行来源政策并明确已有先例覆盖部分；首次/唯一等表述需要系统、范围明确的检索。“未找到”只适用于已记录的检索范围。候选故事按证据贴合与关键实验判别力排序。

学术写作以事实、原意和证据强度优先，保持数字、单位、统计、公式、图号、引用、链接和术语。段落功能、指代与逻辑清楚；删去无信息套话，不机械禁用必要限定语、被动语态或长句。中英文按各自自然信息结构写作，翻译不逐词迁移。审阅只报告问题，不自动改写。

PPTX 实验证据需同时完成结构提取和视觉核对；证据页路径不完整时停止证据写入，报告具体缺口，不降级为凭标题/文字猜图。遵循已有工具和授权边界，不因可选对象失败而阻塞完整可核验的证据。

## Communication

用自然限定说明证据边界，避免反复反例和“不是……而是……”结构。资料不足时区分项目事实、缺失信息和外部证据，不用无来源推测补全。

Obsidian 项目笔记内用 wikilink 引用条目；外部文献用 Markdown 链接。内部控制文件用纯路径和 ID。Codex 对话用标准 Markdown 本地文件链接：绝对路径、正斜杠，含空格目标用尖括号，仅已核对时附行号；对话不使用 wikilink。

粗体后接正文时留空格：`**要点。** 正文`。表格仅用于简短、便于比较的内容，并检查分隔符冲突。
